# Capsule.Bench

The engine's performance harness: a Capsule game whose scenes are workloads, laid out as [`docs/project-layout.md`](../../docs/project-layout.md) lays a game out, run by hand and never by CI or the commit hook. Each scene declares its lane with `[Workload(...)]`, and the suite refuses one without it. `WorkloadKind.Simulation` runs headless — no window, device or media — for 180 warm-up and 600 measured fixed steps, each timed, so the row is one step in isolation with an exact count. `WorkloadKind.Rendering` runs windowed for six real seconds on the surface the attribute names (`Surface.Canvas360`, 640×360 point-sampled, by default; `Surface.Hd1080`, 1920×1080 linear), drops the first 120 frames (the window settles a late present inside them), and measures submission and frame interval; it is the only lane that loads media. A workload isolates one subsystem and names it in its summary. The bench runs with `TieredCompilation=false`, so every frame runs steady-state code and no dynamic PGO applies; absolute numbers differ from a tiered game's.

```text
dotnet run -c Release --project tests/Capsule.Bench -- suite --label <text>
```

Each workload runs in a child process of the same binary on the engine's own command line (`--scene X --headless --driver StepTimer`, or `--scene X --frames <csv> 6`); without `suite` the shell is an ordinary game and `-- --scene Crowd1k` runs one workload windowed. A record goes to `results/<UTC timestamp>.json`, committed; frame CSVs and the `Still` capture go under `artifacts/bench/`, not.

A record is a header — `timestamp`, `label`, `commit`, `configuration`, `os`, `cpu`, `gpu`, `engineVersion` — and one `workloads` row per scene: `name`, `mode`, `surface`, then `steps` and `stepMs` {median, p95} on headless rows, `frames`, `drawMs` {median, p95, max} and `intervalMs` {median, p95, max} on windowed rows (null on the other lane), `gen0Collections` over the measured steps or frames alone, and `captureSha256` (`Still` only; it must not change unless the renderer's output did). `drawMs` is `FrameRenderer.Draw` alone; `intervalMs` is frame start to frame start, the display's rate when the host keeps up and, in its tail, the hitches. Changing a workload's definition resets its history: compare by label and commit. Records before 2026-09-18 carry other columns.

To add a workload, add a scene class under `Capsule.Bench.Logic/Scenes/` with a `[Workload]` attribute, composed from `Entities/`, `Components/`, `Cameras/` and `UI/` as a game would; the suite discovers it from the generated scene registry and runs it by class name. What a level editor would export is a `*.scene.json` under `Assets/Scenes/` the scene claims by key, as `Stage` sits over `stage.scene.json`; a large grid is generated once by a throwaway script and committed as data, one row per line. Frame it with `ParkedCamera` unless camera travel is the point, and keep anything captured fully static.
